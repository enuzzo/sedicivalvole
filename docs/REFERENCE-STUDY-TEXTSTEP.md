## What the project actually contains

textStep does **not** ship an audio-sample library. Its README and implementation describe synthesized sound generated by original DSP code:

- eight synthesized drum voices;
- two polyphonic synthesizers with oscillators, sub oscillator, ADSR envelopes, filters, LFOs, glide, and oscillator sync;
- 32-step drum and synth patterns;
- queued pattern changes and 16 full-state scenes;
- per-pattern BPM and swing;
- sidechain ducking, tempo-synchronized delay, FDN reverb, saturation, compression, and limiting;
- Drum & Bass and Jungle pattern/preset families, including a 174 BPM D&B demo scene.

Any future sample playback in Flux therefore requires separately created or licensed samples with their own provenance. Authorization for textStep does not authorize unrelated break, drum, or instrument recordings.

## Mechanics worth adapting

The useful reference is the system boundary, not the terminal UI:

1. A stable musical clock owns step and bar position.
2. Instrument lanes consume pattern data independently.
3. Pattern and scene changes can be queued to musical boundaries.
4. Sound design is separated from note/step data.
5. Multiple synth and drum lanes share tempo-synchronized effects and dynamics.
6. The real-time audio thread never waits for the UI.

These mechanics align with Flux's existing distinction between continuous driving signals and quantized musical structure.

## Browser implementation

The upstream engine targets Rust with `cpal` and CoreAudio/ALSA, so it cannot run
directly in the Tesla browser build. The implemented production spike translates
the relevant systems into plain JavaScript DSP inside an `AudioWorklet`, with
immutable pattern data and no AudioContext dependency in the core. Rust/WASM
remains a later option only if vehicle profiling proves the JavaScript DSP cannot
meet the simultaneous audio and rendering budget.

The translated portions remain traceable to their upstream files and identify
the browser-specific modifications. FRACTURE's arranger, composition, worklet
shell, stereo effects, and brake processor are original project work.

## Implemented Flux music baseline

### Transport and authored data

- one sample-accurate AudioWorklet clock;
- 32-step patterns grouped into 2- or 4-bar phrases;
- immutable environment data containing scenes, patterns, kits, harmony, and transition rules;
- queued changes at step, beat, bar, or phrase boundaries;
- deterministic seeded variation instead of uncontrolled random triggering.

### Lanes for the first Jungle environment

1. kick and low percussion;
2. snare plus ghost notes;
3. synthesized break-detail lane;
4. closed/open hats and rides;
5. sub/reese bass;
6. primary riff or stab synth;
7. secondary response riff or arpeggio;
8. atmosphere and harmonic bed;
9. bounded transition effects;
10. shared sidechain, delay, reverb, saturation, compressor, and limiter.

The high-energy state should reach a credible Jungle/D&B identity through syncopation, break density, bass movement, riffs, fills, timbre, and dynamics. Tempo should use a knee and a genre-appropriate ceiling rather than remaining near the current soft-club range or rising without bound.

## Acceleration and deceleration memory

Acceleration may prepare and queue added layers quickly, but entry remains beat/bar aligned. Deceleration uses a staged release:

1. **Catch window** — a short speed drop changes filter, pressure, and space but retains transport, principal beat, and musical identity.
2. **Recovery window** — if speed rises again, queued removals are cancelled and the arrangement returns without a restart or rhythmic discontinuity.
3. **Sustained release** — only after continued lower speed does one layer leave at a phrase boundary, followed gradually by other detail lanes.
4. **Tempo release** — tempo eases toward the lower target after arrangement release begins; it never jumps with each speed sample.
5. **Near stop** — the score resolves toward a reduced but intentional musical state rather than muting into an empty noise bed.

This requires separate rise/fall dwell times, hysteresis, a retained peak-energy memory, cancellable queued exits, minimum scene tenure, and crossfades. Brake remains an immediate bounded gesture, not an instruction to tear down the arrangement.
