## Required corrections whichever direction is selected

- Reuse the actual logo/font assets and semantic palette; do not reproduce raster-generated branding, gradients, shadows or novel menu controls.
- Match real phone and compact receiver viewport geometry. The boards do not precisely reproduce the requested receiver aspect ratio; they are hierarchy references, not proof that the drawer fits.
- Keep actual modal chrome ownership and touch target sizes. The first board's underlying running toolbar and the second board's invented hamburger are not approved changes.
- Use an existing semantic status color, not a new hard-coded color inferred from an image.
- Telemetry values and quality labels are mock examples. Implement measured round-trip latency, freshness, calibration and wake-lock truth before claiming readiness.
- Reduce the first board's guide descriptions if needed to honor the owner's requested minimal copy. Separate onboarding instructions from the connected live state rather than duplicating them persistently.
- The artwork shown inside these opaque UI boards is only a style reference. Generate the three final isolated Scan / Connect / Zero PNGs separately with verified alpha after selection.
- Interrupted, denied and unsupported states still need implementation and verification on both surfaces; neither successful-looking mock is acceptance evidence.
